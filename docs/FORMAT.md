# 文件格式

hush.md 没有自己的文件格式。笔记库就是一个普通文件夹，笔记是里面的 Markdown 文件。

## 文件夹布局

默认位置 `~/Documents/Hush.md`（可以用 `HUSH_MD_HOME` 指定任何文件夹）。

```
Hush.md/
├── 笔记.md               ← 你的笔记，任意层级
├── 子文件夹/
│   ├── 另一篇.md
│   └── assets/           ← 在这个子文件夹里粘贴的图片
└── assets/               ← 在库根目录粘贴的图片
```

- 只有 `.md` / `.markdown` 文件是笔记（扩展名不区分大小写）；其他文件不会被读取或修改。子文件夹就是分组。
- **应用不往笔记库里写任何自己的文件。** 设置、每篇笔记的偏好（页宽、阅读模式、置顶、排序）和主题副本都放在系统的应用数据目录里，按笔记库的路径分开：
  - macOS：`~/Library/Application Support/hush.md/vaults/<文件夹名>-<哈希>/`
  - Windows：`%APPDATA%\hush.md\vaults\<文件夹名>-<哈希>\`
  - Linux：`$XDG_DATA_HOME/hush.md/vaults/<文件夹名>-<哈希>/`
  - `HUSH_MD_DATA` 可以整个换掉这个位置（测试用的就是它）。
  - 目录里是 `settings.json`、`notes.json`、`format.json`、`themes/`。删掉它只会丢应用内的偏好，笔记本身不受影响。
- **粘贴的图片和附件**是笔记的一部分，默认放在笔记旁边的 `assets/`，Markdown 里写相对路径 `assets/<id>.png`。设置 → 文档库 → 图片存放位置可以改成一个固定文件夹，那时写绝对路径。旧版本放在 `.hush/assets/` 的图片仍能显示。
- 缩略图、网络图片的副本这类可以重建的缓存放在应用数据目录的 `cache/`。
- 从旧版本升级时，`<笔记库>/.hush/` 里的设置、主题和 `notes.json` 会在第一次打开时复制到应用数据目录，然后把 `.hush/` 删掉。文件夹里不会留下它。
- 以 `.` 开头的文件和文件夹会被跳过（所以 `.obsidian/` 这类目录不会混进列表）。
- 新笔记的文件名来自标题：`标题.md`，重名时依次变成 `标题 1.md`、`标题 2.md`。文件名里的 `/ \ : * ? " < > |` 会换掉。
- 笔记的**标题**是它的第一个一级标题（没有一级就用第一个标题；再没有就用第一行文字；最后退回文件名）。重命名会改写这个标题。

## 删除

删除就是移到操作系统的回收站（macOS 访达、Windows 资源管理器、Linux 桌面环境的回收站），可以在那里恢复。应用没有自己的回收站，也不按时间清空任何东西——何时清空由系统决定。

网络盘、FAT 格式的 U 盘等没有回收站的位置，移入会失败，这时应用会再确认一次，确认后直接永久删除。

## 保存

- **原子写入。** 先写 `.名字.md.tmp`，再 `rename` 覆盖。崩溃时磁盘上要么是旧内容，要么是新内容。
- **未改动的部分逐字节保留。** 每个 block 记住它在文件里的字节区间和原文；写回时如果内容指纹没变，就原样输出。
- **源码视图的保存**直接写编辑后的原文。它拼自 front matter、每个 block 的原文和它们之间的空行。

## 支持的 Markdown

按 CommonMark 的块结构实现，外加 GFM 的表格和删除线：

| 块 | 写法 |
|---|---|
| 标题 | `# 一级` 到 `###### 六级`；也支持 `===` / `---` 下划线形式 |
| 段落 | 连续的非空行；行尾两个空格或 `\` 是硬换行 |
| 无序列表 | `-`、`*`、`+`，用缩进嵌套 |
| 有序列表 | `1.`、`1)`，保留起始编号 |
| 待办 | `- [ ]`、`- [x]` |
| 引用 | `>` |
| 代码块 | ` ``` ` 或 `~~~` 围栏，可带语言名；也支持四空格缩进代码 |
| 图表 | ` ```mermaid ` 围栏，渲染视图里画成图，源码视图里仍是原文 |
| 分割线 | `---`、`***`、`___` |
| 表格 | 管道表格，含 `:---` / `:---:` / `---:` 对齐写法；对齐写法在编辑后保留 |
| HTML | 块级 HTML 原样保留 |
| Front matter | 文件开头 `---` … `---` 之间原样保留 |

行内：`**粗体**`、`*斜体*`、`~~删除线~~`、`` `代码` ``、`[文字](链接)`、`![说明](图片)`、`<自动链接>`、反斜杠转义。

不认识的写法不会被丢弃，而是当作普通文本或原样保留的块，保存时按原文写回。

## 和飞书 DocxXML 的关系

`docxml.rs` 仍然存在，但只用于和飞书互通（从飞书复制粘贴、导入导出的转换）。笔记不再以 DocxXML 保存。

## 已知限制

- 引用块内部会被重新解析，原来每行 `>` 的写法不保留（内容保留）。
- 表格的每个单元格在 Markdown 里只有一行。格内有多段时，保存会用空格把它们连成一行，文字不丢。
- ```` ```mermaid ```` 里写的是**源码**，不是图片：文件里始终只有那段文本，渲染只是显示方式。语法写错或图类型不认识时，退回普通代码块。
- 列表项之间的空行归最后一项所有。
- Markdown 表达不了的块（按钮、倒计时、@文档提及）在 hush.md 里没有对应写法。
